# .gitignore — breakdown

Companion to [.gitignore](.gitignore). Lists paths git should not track —
dependencies, build output, and local environment files.

## Dependencies

### Installed node modules

```gitignore
# Dependencies
node_modules/
```

`node_modules/` is reconstructable from `package.json` + `pnpm-lock.yaml`, so
it is never committed.

## SvelteKit / Vite build output

### Generated build and cache artifacts

```gitignore

# SvelteKit / Vite build output
.svelte-kit/
build/
dist/
vite.config.ts.timestamp-*
vite.config.js.timestamp-*
```

`.svelte-kit/` (generated types + dev server internals), `build/` and `dist/`
(production output), and Vite's `*.timestamp-*` temp files are all derived
artifacts — regenerated by `pnpm dev` / `pnpm build`.

## direnv / nix

### Local direnv cache

```gitignore

# direnv / nix
.direnv/
```

`.direnv/` caches the evaluated devShell for faster directory entry. It is
machine-local and must not be committed.

## Environment

### Local secrets and env files (except the example)

```gitignore

# Environment
.env
.env.*
!.env.example
```

`.env` files hold local/secret configuration and are ignored. The negation
`!.env.example` re-includes a committed template so contributors know which
variables exist without exposing real values.

## Managed local development stack

### Process state and combined logs

```gitignore

# Managed local development stack
.taurus-dev/
```

The managed stack controller records its verified launcher PID and combined
Alpha/Omega log under `.taurus-dev/`. Both are machine-local runtime artifacts,
not repository state.

## Logs & OS cruft

### Log files and OS-generated junk

```gitignore

# Logs & OS cruft
*.log
.DS_Store
```

Ignores stray log files and macOS Finder metadata (`.DS_Store`) that otherwise
clutter diffs.

## Playwright E2E

### Generated end-to-end test output

```gitignore

# Playwright E2E
/test-results/
/playwright-report/
/e2e/screenshots/
```

`/test-results/` (per-run test artifacts), `/playwright-report/` (the generated
HTML report), and `/e2e/screenshots/` (captured screenshots) are all produced by
running the E2E suite — regenerated on every run, never committed.
