# UX-gap audit + Alpha↔Omega integration notes

Added `docs/integration/current/alpha-ux-audit-2026-07-25.md` — a persistent, pre-implementation
audit of everything in the document + AI surfaces that is mocked, unbuilt, broken, or misaligned with
Omega, captured from user review feedback plus a source + Omega-capability sweep.

## Why

The user asked to document all known gaps first, "so we have persistent memory before we attempt to
address it." Several review observations reverse earlier assumptions and one reverses a shipped goal.

## Key findings (verified against taurus-omega source)

- **Real fonts ARE backable.** Omega has `set_block_custom_typography` (`customTypography:
  {fontFamily, fontSize, color}`, per block, ungated) — a free-form escape hatch Alpha uses nowhere.
  So Goal 2.1's swap to semantic tokens was the wrong axis; reverting to real font/size/color needs
  **no backend request**. (Earlier "BR-TYPOGRAPHY-REAL" retracted.)
- **Omega blocks have three orthogonal axes**: kind (`set_block`, 14 kinds — Alpha exposes 8),
  semantic style (`styleRef`/registry — Goal 2.1/2.2), and custom typography (real fonts). Alpha
  conflates them; "body" is a style *token*, not a block *kind*.
- **Comments are now backable** (`/documents/:id/comments` + `PATCH /comments/:id`) — reverses the old
  "blocked" contract; the panel is still mocked.
- **Prompt-block editing UI is missing** though `set_prompt`/`resolve_block` + runtime actions exist.
- **Name Manager is real** (`/projects/:id/names/*`); the **AI Quarterback dock is fully mocked**
  (Goal 3.3) and needs a persona dropdown, task↔chat, and real progress.

## Captured design (user)

The inspector should become: real font/size/color; a **Text type** dropdown (block kind — at the
bottom for selections, "changes the whole line"); and an **Insert element** dropdown on an empty
"new line" for non-text kinds (image/divider/callout/code/prompt). Selection-spanning type changes
split at bounds then convert.

## Open decisions (recorded in the audit)

1. Text-type = block kind only (recommended) vs. keeping "body" as a style entry.
2. Keep the semantic style registry (Goal 2.1/2.2) for tone/semantic facets vs. drop for kind +
   custom fonts only.

No code changed. Durable direction also saved to session memory.
