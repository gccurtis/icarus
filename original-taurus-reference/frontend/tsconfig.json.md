# tsconfig.json — breakdown

Companion to [tsconfig.json](tsconfig.json). Configures TypeScript for the
project by extending SvelteKit's generated config and layering a few explicit
options on top.

## Extends

### Inherit SvelteKit's generated base config

```json
{
  "extends": "./.svelte-kit/tsconfig.json",
```

SvelteKit generates `.svelte-kit/tsconfig.json` (via `svelte-kit sync`) with
path aliases like `$lib` and the correct module settings. Extending it means we
inherit those instead of hand-maintaining them.

## Compiler options

### Explicit overrides layered on the base

```json
  "compilerOptions": {
    "allowJs": true,
    "checkJs": true,
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "resolveJsonModule": true,
    "skipLibCheck": true,
    "sourceMap": true,
    "strict": true,
    "moduleResolution": "bundler"
  }
```

These are the standard SvelteKit defaults: `allowJs`/`checkJs` type-check plain
JS too; `esModuleInterop` smooths CommonJS imports; `forceConsistentCasingInFileNames`
prevents case-mismatch bugs across OSes; `resolveJsonModule` allows importing
JSON; `skipLibCheck` skips type-checking `.d.ts` from dependencies for speed;
`sourceMap` aids debugging; `strict` enables all strict checks; `moduleResolution:
"bundler"` matches how Vite resolves modules.

## Trailing note

### Reminder not to override generated settings

```json
  // Path aliases and most config are generated by SvelteKit into
  // .svelte-kit/tsconfig.json — extend, don't override, so they stay in sync.
}
```

A comment documenting the intent: keep path aliases and core settings in the
generated base file so they stay in sync with SvelteKit, and only add
project-level options here.
