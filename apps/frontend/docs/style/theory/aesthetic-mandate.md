# Aesthetic mandate

> **Committed stance.** Discipline rather than values. The values this argues
> for are enumerated in [`catalog/`](../catalog/palette.md) and composed in
> [`component/`](../component/components-and-states.md).

The interface should feel like an angelic citadel in the clouds operated through
astro-tech: a clear chamber for thought, powerful enough to coordinate documents,
data, derived values, agents, and live outputs, yet arranged so complexity feels
mentally weightless.

## Aesthetic thesis

- **Luminous order:** pearl and off-white surfaces, low-glare depth, restrained
  blue-violet light.
- **Architectural clarity:** strong spatial zones, calm boundaries, predictable
  panels, repeatable hierarchy.
- **Instrument precision:** crisp controls, exact focus, readable data, complete
  interaction states.
- **Invisible intelligence:** derived work appears through resolved output, live
  objects, explanations, and reviewable change.
- **Reversibility and trust:** material action is attributable, inspectable,
  recoverable, and honest about uncertainty.

## It should not feel like

- a generic SaaS dashboard;
- an Apple white-and-blue clone;
- saturated cyberpunk;
- a command line disguised as a GUI;
- an expert-only editor built around secret shortcuts;
- a chat product that makes the work surface secondary.

## Design laws

1. **Center first:** reduce chrome intensity before reducing work-surface
   clarity.
2. **Few things visible, right things visible:** primary actions and context stay
   present; secondary actions are grouped predictably.
3. **No secret essentials:** shortcuts and context menus accelerate visible
   paths; they never replace them.
4. **Panels are cognitive instruments:** context is a map, inspector is a lens,
   the drawer is a workbench for one object.
5. **Intelligence is quiet until directed.**
6. **Beauty is legibility:** the user knows what they see, what is selected, what
   changed, where it came from, and what comes next.

## Visual metaphors

- **Citadel:** clear zones and structural hierarchy without boxed-in clutter.
- **Cloud:** softness and air at the background level, precision at the control
  level.
- **Star map:** restrained semantic color provides orientation. Color is how a
  user navigates meaning, which is why it is rationed — see
  [color usage laws](../catalog/color-system.md#usage-laws).
- **Instrument:** every interaction has a complete set of states, and every state
  has a name — see [the state matrix](../component/components-and-states.md#state-matrix).

## Uncertainty is part of the aesthetic

A system that derives content is never more confident than the work it displays.
Confidence, provenance, review state, and staleness are first-class visual
material, not fine print. Derived output that cannot show where it came from is
not finished, and must not look finished.

## Review test

A screen succeeds when a first-time user can identify the work surface, the
current object, the selection, and the likely next action within seconds.

It should remain understandable when color is removed, and grow calmer — not more
cluttered — as its logic becomes familiar.
