# Runtime Object: `RichContentIdFactory`

## Responsibility

Allocates every identifier Rich Content owns: content, atom, mark, and list IDs.
Concentrating allocation in one injected object is what makes the capability
invariant — *every ID is generated by Rich Content* — checkable in one place
rather than at each of the dozen sites that create an atom or a mark.

It owns the *semantics*: which kinds exist, what each is called, and what prefix
each carries. It does not own value generation. The values come from
[Platform ID Factory](../../../../platform/id-factory/overview.md), which is
injected as an `IdFactory` and asked only for a collision-resistant string. That
division is the whole reason the shared capability is one generic method: the
kinds are Rich Content's business and would have no meaning in Platform.

This is an **internal** runtime object. It is constructed inside
`createRichContentRuntime` and injected into `PersistedRichContentRuntime`; it
is not re-exported from `index.ts`, so no consumer can hold one or substitute
one. Consequently it has no `runtime-api/` directories, and the rule requiring a
directory per interface method does not apply to it.

It deliberately does not decide *when* an ID is allocated. That is each
procedure's business — notably `split` and `combineAsList`, which regenerate
atom and mark IDs precisely because their results are new objects rather than
edited ones.

## Interface

Declared in [`definition.ts`](definition.ts).

```ts
export interface RichContentIdFactory {
  contentId(): RichContentId;
  atomId(): AtomId;
  markId(): string;
  listId(): ListId;
}
```

`markId` returns a bare `string` because mark identity is private and never
surfaces in `DisplayContent`; the other three have named aliases in
[`types/ids.ts`](../../types/ids.ts).

## Fields

None. The production implementation is a stateless object literal, closing over
the injected `IdFactory` and prefixing what it returns.

## Constructor

`createRichContentIdFactory(ids)` in [`constructor.ts`](constructor.ts). It
performs no startup work.

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `ids` | `IdFactory` | The runtime's shared generator, from Platform ID Factory. Supplies the value behind every ID; the prefix is added here. |

### Construction Steps

```text
1. Return an object whose four methods each prefix one ids.create() value:
   content_, atom_, mark_, list_.
```

The prefixes make an ID self-describing in a stored JSONB row and in a log line,
and they stay here because a generator that applied them would be deciding what
the ID names.

## Invariants

- Every ID it returns is unique. Uniqueness is inherited from the injected
  `IdFactory`, which is the only source of the varying part of the string.
- Each ID carries the prefix naming its kind, so the kind is recoverable from
  the string alone. The prefix and the generated value are separated by `_`.
- The factory is pure with respect to content: it reads nothing and writes
  nothing, which is what lets a test replace it with a counting factory and get
  reproducible IDs without touching any other behavior. A test substitutes this
  object, not the `IdFactory` behind it — see
  [`test/fixture.ts`](../../test/fixture.ts).
