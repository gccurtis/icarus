07 · the centre

The content surface

Two layers. content/deck.svelte is the editor's view: it owns the frame, the zoom, the keyboard, the context menu and every decision about what an intent means for the body. components/authored/slide-surface is the renderer: it draws a scene and turns pointer and key events into typed callbacks, and it never sees a body or an op.

1

The frame

A three-row grid: a title bar with the deck's title (read from slideDecks.<id>.title), the canvas, and a strip. The canvas is a scrolling area whose content is a pasteboard — a flex box at least as large as the viewport, with a 24px gutter of padding, centring the slide. The strip holds Previous / Next, a Notes button that opens the speaker-notes lens, the placing hint when a kind is armed, zoom out / percentage / zoom in, and the runtime's sync state (Loading, Saved, Saving, Rebasing, Needs review, Offline, Not saved).

Fit and zoom

fitted(available, ratio, GUTTER) is the largest slide that fits the canvas less the gutter on every side; drawn(fit, zoom) scales it by the zoom per cent. Zoom null or 100 is fit, and the percentage button says “Back to fit”. ⌘-wheel or a pinch changes the zoom by two per cent per wheel notch; the ± buttons step by the configured zoomStep; every change is clamped to the configured bounds. zoomTo keeps a focus point still: the centre of the selection when there is one, otherwise whatever is at the centre of the viewport — after the next tick it scrolls so that point is back under the centre.

Units

The slide is 720 units high (stage.unitsHigh) and 720 × ratio wide; the renderer lays the stage out at that size and applies one transform: scale() to reach the drawn pixels. Handles, outlines and badges divide by the scale so they stay the same size on screen at every zoom.

2

The scene

sceneOf(body, slide, units) in procedures/scene.ts is the only place a body becomes something drawable. It walks placedOn(slide) so every element has an absolute frame, a depth and its parents; a layout's locked elements are prepended as fixed items (never hovered, selected or moved); the background is the slide's, else the layout's, else the theme's. For each element it resolves paint into CSS strings (colorOf turns a --token into var(--token)), a shadow into a drop-shadow value, text into a flat TextScene (block format → named style → theme → default, runs cut at every mark and formula boundary), and a table into a grid of CellScenes with row, column, spans, fill, border and header flag from gridOf. The Slides and Style panels call the same function for their previews.

Selecting a cell the first time is a press on the selected table that does not move: pointer up reports that one cell. From then on a drag ranges. Escape leaves the cells and goes back to the table; a click elsewhere selects as usual.

Double-click enters text: on a text box or a shape it opens the block; on a table cell it opens that cell's block; on a grouped child it selects the child instead, so the next double-click reaches its text. Double-click while placing does nothing.

Hover draws a light outline on the object under the pointer when nothing is being dragged, edited or placed. Locked and fixed items take no pointer events at all.

The keyboard

A window keydown listener in the view. It ignores an event a popover has already handled (defaultPrevented), and while nothing is being edited it ignores keys aimed at an input, textarea, select or contenteditable.

6

The text engine

slide-surface-text.svelte renders a block's runs as spans inside a contenteditable that is editable only while editing. The DOM is a projection: every input event is intercepted before the browser applies it, turned into a splice against the block's display, and sent up as onedit; the body changes, the runs re-render, and the caret is placed at the remembered offset on the next tick.

beforeinput typeBecomes
insertText, insertReplacementTextReplace the selection with the data.
insertParagraph, insertLineBreakInsert \n. A line break stays inside the one block; a text box does not split.
insertFromPaste, insertFromDropInsert the plain text.
deleteContentBackward / ForwardDelete the selection, or one character.
deleteWordBackwardDelete back to the previous word start.
deleteByCutCopy the selection to the clipboard and delete it.
anything elseAllowed through; an input handler then diffs the DOM text against the block and emits the smallest edit, so an IME or an unhandled command still lands as an op.
  • Offsets are counted through the run spans; a formula chip carries data-length and is skipped as one unit.
  • Entering focuses the host and, if the pointer landed inside the text in the last 600 ms, places the caret at the pointer with caretRangeFromPoint; otherwise at the end. A pointer down on the block is remembered for that purpose.
  • Reporting. selectionchange and mouse up report oncaret(from, to), which the view mirrors into the workspace selection so the caret's lens follows.
  • Shrink. With fit (the shrink overflow) the engine reduces the font by 8% steps, up to twelve times, until the text fits its box.
  • Escape exits; ⌘B/I/U are prevented so the browser never bolds the DOM itself.

Growing

A text box with overflow: "grow" (the default for a new one) is watched by a ResizeObserver in the item renderer. When the prose's needed height differs from the frame's by more than 0.75px, it asks for the new height on the next animation frame — the deferral is what stops the observer's own loop errors. The observer is off while a gesture is busy, so a resize drag is never fought.

7

Putting things on the slide

  • Click-to-place from the Insert panel: placing.kind is set, the stage shows a crosshair, the strip says “Click on the slide to place the … · Esc cancels”, and the next pointer down anywhere on the slide calls onplace(at). The view disarms and calls put.
  • Right-click menu: the same catalogue as the Insert panel, shapes in a submenu, labelled “Add to slide n, here” when the click was on the slide. The pointer's fraction is remembered by oncontext; the menu's item inserts centred on it. A right-click never changes the selection.
  • put builds the element with makeElement(kind, body, frameFor(kind, at)) — a text box saying “Text” in the default style that grows, a shape filled with the theme accent, a line corner to corner with an arrowhead, an empty picture, a three-by-three table — inserts it last with withInsertedElements, and selects it so its lens opens.
8

Comment badges

The view holds read({ path: "commentThreads" }) for its whole life and derives, per slide, a count of open threads per element (and per slide). The renderer draws an amber badge at the object's top-right corner, unscaled, and a dashed amber ring around the object with a small gap; the slide's own badge sits at the frame's corner. Clicking a badge selects the object and opens its threads lens. Because the query is held rather than re-created, a refresh from any lens that posts a comment reaches this view too.

9

Snapping and guides

targetsOf collects the slide's edges and centre and every top-level, unselected sibling's edges and centres; snapped finds the nearest target to any of the moving frame's own left / centre / right and top / middle / bottom within a threshold of 0.006 of the slide, shifts the frame by that delta, and names the guide (“left edge”, “slide centre”, “middle”). Alt disables it. The view passes this as the snap callback so the renderer knows nothing about siblings.
