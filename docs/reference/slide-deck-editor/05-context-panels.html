The context panels

Nine entries on the rail. Six are built, three are placeholders. Each is one file under context/, named for its key, and each reads the same runtime the canvas reads.

1

How a panel is wired

The context surface holds import.meta.glob("$lib/app-views/categories/*/context/*.svelte") and loads the file whose path is the active context key with the dot replaced by /context/. A key with no file shows “Not built yet”. Vite indexes the glob when the dev server starts, so a new panel file needs a restart to appear.

Every built panel opens the same way, and a reader auditing them should expect these lines at the top of each:

const view = workspaceState();
const deckId = $derived(view.active.resourceId);
let runtime = $state<SlideDeckRuntime | undefined>(undefined);
$effect(() => { runtime = deckId === undefined ? undefined : view.slideDeckRuntime(deckId); });
const body = $derived(runtime?.body);
const slide = $derived(body?.slides[slideIndexOf(body, view.active.focus)]);

The runtime is attached in an effect, not a derived, because attaching is a write to the register. The current slide is view.active.focus resolved through slideIndexOf, which falls back to the first slide when the focus names nothing. A panel writes by building ops with a procedure and calling runtime.apply; a panel navigates by view.open({ focus }) and view.inspect(key, selection). No panel imports another panel, the content view or the inspector.

2

Slides

Shows every slide as its number above a full-width preview, drawn by the same SlideSurface the canvas uses with interactive={false} and the scene from sceneOf(body, slide, units). The chosen slide's preview carries the active outline, a hovered one the interactive outline; the number is the only other thing on the row. A hidden slide is veiled and says “hidden” beside its number.

Sizing. The reel's usable width is measured with a ResizeObserver and the panel's own horizontal padding subtracted from clientWidth; the thumbnail is that width minus two pixels for the outline, and its height follows the deck's ratio. Previews therefore shrink with the flank instead of clipping.

Verbs, in the panel's actions row:

  • New inserts a slide after the current one, taking the current slide's layout key; New ▾ lists the deck's layouts and makes a slide from one (withNewSlide(body, current, layoutKey)). The new slide is found by diffing ids before and after and is shown at once.
  • Duplicate copies the slide with fresh ids for every element, block, atom and mark (withDuplicatedSlide).
  • Delete removes the slide and shows its neighbour; it is disabled on the last slide because a deck keeps at least one. Removing the first slide of a section re-anchors the section.
  • The three buttons share the row (flex-1); a container query shows the words “Duplicate” and “Delete” once the flank is at least 15rem wide.

Reordering. Rows are draggable with a private MIME type; an insertion bar shows above or below the row under the pointer by its midpoint; dropping calls withMovedSlide(body, dragged, after). ⌥↑ / ⌥↓ step the current slide (stepped); the keydown listener is attached in an effect to satisfy the a11y check on a non-interactive element.

Selecting a slide opens the tab on it and inspects the slide lens.

3

Insert

Shows a search field over a two-column grid of tiles — Text box, Rectangle, Ellipse, Triangle, Diamond, Arrow, Callout, Line, Picture, Table, Chart — from INSERT_ENTRIES. Chart is disabled with its note as a title. No sections, no descriptions.

Does. Pressing a tile arms that kind in placing.svelte.ts, the one module-level $state the editor shares; pressing it again disarms. The note under the grid says “Click on slide n to place the …. Esc cancels”. The canvas sees placing.kind, shows a crosshair, and on the next click calls put(kind, at) which builds the element with makeElement at frameFor(kind, at), inserts it last on the slide and selects it. Leaving the panel disarms (a cleanup effect), and so does the canvas being unmounted.

The same catalogue feeds the canvas's right-click menu, which inserts at the pointer without arming anything.

4

Layers

Shows two bands. Actions: four icon buttons — bring to front, bring forward, send backward, send to back — that act on the current selection through withRestackedSet, which keeps the selected objects' relative order and moves them as a block. Layers · n objects: every element on the slide from placedOn(slide), reversed so the topmost is first, indented by depth for grouped children, with a type icon and labelOf (a text box's first line, “Shape — words” for a shape with text, “Group (n)”).

Does. A row selects through elementsSignal, exactly as a click on the canvas does, so the same lens opens and the canvas outline follows. The lock button appears on hover (and stays when locked); it writes <el>/locked, and a locked element cannot be hovered, picked or marquee-selected on the canvas. Rows drag to reorder with an insertion line, but only among siblings: a drop that would move an element into or out of a group is ignored.

5

Style

The panel that absorbed Slide size, Layouts and Theme. Three sections; the last two start collapsed.

Slide

  • Aspect as two numbers, [w] : [h], each a PanelNumber 1–64, writing aspectRatio through asAspectRatio. Every frame is a fraction, so the objects keep their places.
  • Background: a picker writing theme/background as { kind: "color", color }.

Layouts

  • A name field and Save slide n as layout. withSavedLayout mints a layout whose locked is a fresh-id copy of every element on the slide, with the slide's background and no placeholders; an empty name becomes “Layout n”. Enter in the field saves too.
  • A two-column shelf of previews, each drawn by SlideSurface from a scene of the layout's locked elements; the card width is measured from the shelf. A remove button appears on hover (withoutLayout).
  • Layouts are per deck. Import and export between decks, and any relation to templates, are out of scope for this panel.

Named styles

  • A select of the deck's styles plus New (mints style-n named “Style n” at 20px and picks it).
  • Name (inline editable), Font + Size, Font colour (clearable), horizontal alignment and vertical alignment as icon rows, and Spacing (line height, before, after). Every control writes styles/styles/<key>/<field>, so it changes every block wearing that style; a single block's overrides are on its lens.
6

Find

Shows a Find / Replace mode chip in the actions, a search field, a scope chip (All / Slides / Notes), and one row per hit — “Slide n · Text | Shape | Table | Notes” with a snippet around the match. Hits are computed from every text block the scope allows: text boxes, shape text, every table cell, the notes block. The count reads “matched of total blocks”.

Does. Opening a hit shows its slide, selects the holding object (or the notes lens for notes), then inspects a text selection over the match so the canvas highlights it. In Replace mode, Replace rewrites the highlighted hit and Replace all rewrites every hit, per block from the end backwards so earlier offsets stay valid, all through replaced — which means marks shift correctly and every replacement is undoable as one gesture.

7

Comments

Shows a scope chip — Deck, Slide n, and the selected object when there is one — a composer, and the deck's threads split into Open (n of m) and a collapsed Resolved. Each thread is a PanelQuote with the author's name (from the users table), the anchor (“Slide n · Shape”) and a relative time; clicking it inspects general.comment.

Reads three queries — commentThreads, comments, users — held for the panel's whole life as const … = read({ path }) at the top of the script. They are never created inside a derived; page 08 explains why that matters.

Writes through startThread with within set to the element or the slide according to the chip, then refreshes the thread and comment queries so the canvas badge, the threads lens and this list all move at once. ⌘↩ posts.

8

Templates, Variables, Prompts

Each is eight lines: a Panel, a PanelEmpty saying what it will be, and a PanelNote with its key. They exist so the rail has the reviewed shape and so the key resolves to a file rather than to the surface's generic “Not built yet”. The reviews were explicit that these stay unbuilt for now.
