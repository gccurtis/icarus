Everything the deck editor is now, and everything this worktree changed to get there, written so the work can be audited file by file. Three pages say how the system works, one says what changed and why with every diff behind a dropdown, and five go through the parts one at a time.

How to read this

Pages 01–03 describe the editor as it runs today, without reference to what it used to be. Page 04 is the audit: ten systematic changes, each explained, each broken into the changes that make it up, each of those with the diff of every file it touched. Pages 05–09 take one part each — the context panels, the inspector, the content surface, the runtime, the back end — and say how that part works end to end and which of the changes on 04 made it so.

The diffs are generated, not written. build-diffs.mjs beside this page runs git status and git diff HEAD in the worktree and fills every dropdown; run it again after any change and the pages are current. The prose is checked against the code and the running app, not against older documents — the design record under docs/archive describes intents that this branch has since made concrete or overturned.

What "against main" means here

The branch was cut at ad1900f. Main has since taken three commits — the resource alignment, the docs move to docs/archive, and the served wiki — none of which touch the slide deck editor. So the differential that matters is the working tree against the branch point, which is what every diff on these pages is. Merging onto main is a separate step, and nothing here runs git on main.

Running it

cd .claude/worktrees/slide-deck-editor/app
nix develop ../../../infra/devshell --command pnpm seed -- --force   # the seed changed: text boxes grow
rm -f data/workspaceRevisions.json data/workspaceSnapshots.json      # forget the last session's tabs
nix develop ../../../infra/devshell --command pnpm dev -- --port 3001

Open the project, double-click Board review — Q1 exposure. Checks, from app/: pnpm vitest run (635 tests), pnpm exec svelte-check (clean for every file on these pages; the remaining errors are categories whose capabilities are not built and are older than this branch), node scripts/lint.mjs (34 findings, all older than this branch).

A new context panel or lens file is a new entry in an import.meta.glob, which the dev server does not always notice — a panel showing “Not built yet” after you add a file means restart pnpm dev.
