The conflicts Git could not see

Line-level conflict resolution was necessary but insufficient. Main had changed the rich-text and collaboration representations while the slide branch had changed the slide body and selection representations. Each side compiled against its own assumptions; the combined application had to make those boundaries explicit.

BoundaryReconciliation
Stored slide bodiesMain's templates still admitted the earlier blocks[]/format element shape while the editor requires explicit content/paint variants. slide-deck/api/shared/leader.ts normalizes before reads or submissions consume a body.
Rich-text marksMain changed mark endpoints from numeric display offsets to { atom, offset }. Slide typing, scene rendering, op application, tests, legacy normalization, and template validation now share atom-aware position helpers from representation/data/behavior/content/positions.ts.
Comment anchorsThe start-thread boundary accepts main's canonical multi-block text anchor, { kind: "text", spans: [...] }, and rejects the former numeric input. Slide element/slide anchors remain explicit variants.
Reactive readsTransient slide views no longer create direct store reads. Comment queries come from the workspace-owned registry, matching the lifetime rule introduced by the document editor and avoiding destroyed-view resources.
Workspace selectionsThe inspection canonicalizer copies both optional ranges and ids. Shift-click, Control-click, multi-cell selection, submitted ops, undo, and restoration retain the complete selection rather than only its primary id.
Templatestemplates/api/shared/validation.ts normalizes first, then validates the actual content union, atom endpoints, paint/background, indentation, nested groups, layout ids, references, dangling atoms, and globally addressable ids.
Multiple old blocksThe pure normalizer creates a group with deterministic child ids and relative frames. Background and border become a locked backing shape; padding becomes geometry; every text, image, table, formula, or prompt block survives.
Fresh seedsThe seed corpus remains useful legacy evidence. All four snapshots, four current slide templates, and four slide template versions were run through the same normalizer and canonical validator successfully.

Why the adapter lives in representation behavior

It is a pure function over represented data: no store, request, clock, filesystem, or UI. Read boundaries and template admission call one deterministic rule instead of carrying separate migrations.

The final fast-forward

The verified branch is handed to main without a merge commit:

cd /home/jakul/cyberia/icarus
git status --short --branch
git rev-list --left-right --count main...work/slide-deck-editor  # 0  2
git merge --ff-only work/slide-deck-editor

nix develop ./infra/devshell --command bash -lc \
  'cd app && pnpm dev --host 127.0.0.1 --port 3111 --strictPort'

--ff-only is deliberate: 4ceb07a is an ancestor of the reconciled branch. A refusal means main moved after this audit; rebase onto that newer main and repeat the gate instead of hiding a new conflict inside an unreviewed merge commit.
