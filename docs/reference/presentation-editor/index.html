How to read this

Pages 01–03 describe the editor as it runs today, without reference to what it used to be. Page 04 is the audit: ten systematic changes, each explained, each broken into the changes that make it up, each of those with the diff of every file it touched. Pages 05–09 take one part each — the context panels, the inspector, the content surface, the runtime, the back end — and say how that part works end to end and which of the changes on 04 made it so. Page 10 is the roll-forward and merge record.

The diffs are generated, not written. build-diffs.mjs beside this page runs committed and working-tree changes against main and fills every dropdown; run it again after any change and the pages are current. The prose is checked against the code and the running app, not against older documents — the design record under docs/archive describes intents that this branch has since made concrete or overturned.

What "against main" means here

The branch was cut at ad1900f. Main then took 23 commits, including the complete document editor and its current shared component and content contracts. The feature was preserved and rebased onto 4ceb07a; rebase stopped on both feature commits and eight distinct paths required resolution. Git could not expose the atom-position, comment-anchor, query-lifetime, template/snapshot, or multi-selection contract mismatches. Page 10 records each resolution. The diffs compare the reconciled result with that main baseline.

Running it

cd /home/jakul/cyberia/icarus
nix develop ./infra/devshell --command bash -lc \
  'cd app && pnpm dev --host 127.0.0.1 --port 3111 --strictPort'

Open the project, double-click Board review — Q1 exposure. The Nix verification gate is clean: 799 unit tests, 99 script/generator tests, 19 Chromium tests, zero Svelte/TypeScript diagnostics, and all 56 architecture/style checks passing. Page 10 § 5 has the exact commands.

A new context panel or lens file is a new entry in an import.meta.glob, which the dev server does not always notice — a panel showing “Not built yet” after you add a file means restart pnpm dev.
