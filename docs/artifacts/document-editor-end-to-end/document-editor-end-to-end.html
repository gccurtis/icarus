The document editor, end to end

One document, three copies. The store holds the canonical one. The client runtime holds a live one and every change is an operation on it. The editor is a picture of the live one and a way to ask for changes — nothing more. This is how the whole thing works when it is finished.

01 · Copies

Three copies of one document

Everything else on this page is a consequence of this diagram.

The canonical document is a row in documentSnapshots with role: "leader". The client runtime holds a copy, and every change the user makes — from a panel, from the editor, from undo — is stated as operations applied to that copy first and sent to the store afterwards. The editor draws whatever the live copy currently is, and tells the panels where the selection is. That is its only edge that is not to the runtime.

The editor is an interface to the document, not a place the document lives. A panel that makes text bold applies a mark op to the live body; the runtime moves; the editor is re-projected from the body and the text is bold because the body says so. Undo is the same path with the op inverted. Sync is the same path with the store's body in place of the live one.
Consequence 1

The live copy advances the moment an op is applied, before the store answers. Otherwise a panel edit vanishes for two seconds and reappears.

Consequence 2

Re-projection leaves the selection where it was. Every button press would otherwise lose the caret.

Consequence 3

Every address is structural, not positional. Where a mark starts, what is selected, where a comment is anchored — all survive the document changing around them.

03 · Model

A text block, opened up

Atoms, display, marks — and where a mark points.

A text block holds atoms, the smallest authored units. A literal atom is typed characters. A formula atom is a {{ }} span that resolves to a string. Display is every atom's rendered text concatenated. Marks are ranges over that text carrying formatting, a link, or a colour.

Where a mark points

Each end names an atom and an offset into that atom's rendered text. The bold above is on characters 0–12 of #a2's display, "four percent".

Display-space where it matters: twelve characters of what was seen, not nineteen of forecast.delta behind them. Structural where it matters: the address is the atom, and only editing that atom moves it.

After the formula re-resolves

#a2 now resolves to "4.1 percent". #m1 stays (#a2, 0)–(#a2, 11), clamped to the atom's new length, still on the formula.

from 57 to 69 — with offsets into the whole display, the mark would now cover "4.1 percent," and the comma, and every mark after it would have moved too.

Model change proposed

Mark.from and Mark.to become { atom, offset } in place of two numbers. The comment anchor AnchorWithin.text takes the same two endpoints.

The selection already works this way — signalOf hands the inspector blockId/atoms/atomId@offset today — so this brings marks and comments to the address the editor already uses.

Marks are a list, and each has an id. Overlapping marks are legal: a word that is bold and italic can be one mark with two styles or two marks, and nothing consolidates them. The id is what lets two people format one paragraph without colliding — a change addresses #m1 rather than replacing the array.

04 · Model

Styles, and what a block adds on top

A style is a named set of formatting. Nothing more special than that.

The body holds named styles in a StyleSet; a block names one by key. Applying a style fast-tracks the formatting it holds. What is drawn is the style first, then the block's own format laid over it, field by field — a block with no format draws exactly as its style.

Two places to change spacing, on purpose

Select text and change After in the inspector: that writes the block's format, and only that block moves. Select the Body style in the Styles panel and change After in the named-style lens: that writes the style, and every Body block moves.

Space before / after is the gap around a paragraph. Line height is the gap between lines inside it — single, 1.5, double. Indent is the first-line inset. There is no letter-spacing anywhere in the model.

Model change proposed

BlockFormat gains spaceBefore, spaceAfter, lineHeight and indent, optional, in the same units as TextStyle. Today those four exist only on the style. Alignment is already on both.

The default set

Body, Heading 1, Heading 2, Heading 3, Quote, Caption, Code; defaultKey: "body". Written by the runtime the first time anything is styled — never on open, because opening a document must not dirty it.

Picking Heading 1 writes style: "heading-1" and variant: "heading", level: 1 together.

05 · Model

Pages: setup and furniture

Everything page-related is derived from the setup. Nothing is drawn on the page.

Page setup

Paper, orientation and four margins, in inches, one for the document. Paper is a named size or a { width, height } of its own.

A margin is a number in the Layout panel and an area of blank paper, and that is the whole of its presence. No guide, no ruler.

Header and footer

Each a PageFurniture: its own rows, an optional first-page set, a distance from the edge, an optional page-number setting. Ordinary document rows in a second root.

One definition, drawn on every page. Each root has one canonical editor; repeated appearances are read-only projections that focus it. Every furniture op names its root — header/rows, footer/firstPageRows.

Page numbers

Generated from pageNumber — position, format, start, first-page visibility — and never typed as footer content. A page number typed into a footer is wrong on every page but one.

Pagination is derived

Where page 1 ends is a function of the paper, the margins, the rows in order, and the size each block draws at. Computed on the client whenever any of those changes; never written. The only stored boundary is an explicit page break row.

The estimate is per block, from its resolved style — a bigger heading gets a smaller character budget and more height — which is why no characters-per-line figure belongs in a panel.

06 · Runtime

The live document

One DocumentRuntime per open document.

HoldsWhat it is
bodyThe live DocumentBody. Every panel reads it; the editor is projected from it.
revisionThe store revision the body was last known to match.
bufferOps applied to the body and not yet flushed. Coalesced before sending — adjacent text splices on one atom become one splice.
undoStack · redoStackGroups of ops, in order. Every op is invertible, so undo needs nothing but the ops themselves.
syncloading · saved · saving · rebasing · needs-review · offline · error
editorThe mounted ProseMirror view while the surface is on screen — what re-projection targets. Nothing else touches it.
Apply: the body moves first

apply(ops) runs the applier over the live body, then records the ops for undo and adds them to the buffer. The body has already changed by the time the store hears about it. If the applier refuses — an op naming a block that is not there — nothing was applied and nothing is buffered.

One applier, both sides

It lives in representation/data/behavior/documents/; the client runtime calls it to advance the live body and submit-document-changes calls it to advance the leader. The slide deck already works this way. An op the client accepted and the server refused is impossible by construction, short of a stale base.

A panel

Reads the selection and the live body, builds its ops, calls apply. Bold on a selection is one insert mark; a margin is one set document.

The editor

A ProseMirror transaction changes the projected doc; the doc is read back into a body; the body is diffed against the last one; the diff is the ops. The only path where ops are derived, and the path only typing takes.

Undo

The last group on the stack, inverted in reverse, applied. Every op carries enough to invert without a lookup — was, the values, wasAfter, what a splice removed.

The store

Never sends ops to the client. It sends bodies — a settled runtime re-reads the leader — and, on an accept, catch-up ops that conflict with nothing.

Undo. ⌘Z pops the last group, inverts each op in reverse order, applies the inversion to the live body, pushes the original onto redo, buffers the inversion so it flushes like any change, and re-projects. There is no ProseMirror history. A typing burst is one group, on the coalescer's rule.

Re-projection keeps the selection

When the body changes for any reason other than typing, the editor is rebuilt from it. The selection is read before as structural addresses and restored after by resolving the same addresses in the new projection. A block that no longer exists collapses to the nearest surviving position.

Typing is the exception, and it is contained

A keystroke goes into ProseMirror first so the letter appears at once. The transaction is applied, the doc is read back into a body, diffed against the last body the runtime was given, and the diff — one text splice — is applied to the runtime. The bodies now match; no re-projection follows. Enter and Backspace at a block boundary become a row insert and a row remove by the same diff.

The pasteboard

Pages sit centred with a gutter either side. Zoom is view state — per tab, never on the document. The trailing gutter reserves a fixed lane for comment icons and only the leading gutter gives way as the surface narrows. The page draws the document and nothing else.

09 · Editor

Selection

One or more ranges, each end an address the whole system shares.

Each end of a range is blockId/atoms/atomId@offset. The editor reports it; the workspace stores it on the tab beside which lens is open; the lens reads it and the live body together. It is the same address a mark or a comment uses, so "make this bold" and "comment on this" are the selection's endpoints copied into a mark or an anchor.

The caret isLensThe lens shows
a range, or severaldocument-editor.text-selectionThe text, quoted. Style, marks, alignment, colour, spacing; comments and links on the range. Any control the ranges disagree on draws itself mixed.
in a block with characters either sidedocument-editor.next-letterThe same controls, reading what the next typed character will carry.
in a block with no charactersdocument-editor.empty-line renamedBlock — Text · Table · Image · Page break — then everything the text lens has when the block is Text. Choosing another type replaces the block, or the row.
on a table, an image, a formula blockdocument-editor.table · image · formulaThe block's own fields. Image is a new key; prompt and chart stay placeholders.
Several ranges at once

Multi-selection is non-contiguous: this word and that word, in two paragraphs, together. ProseMirror has one selection at a time, so the editor carries a custom Selection subclass holding a primary range and any number of others, and a plugin decorates the others. The lens receives them all and applies each op once per range. A range that merely spans several blocks is not this — it is one range.

Model change proposed

Selection in workspace/tab.ts is { kind, id, at? } — one range. It gains ranges?: readonly { id: string; at: string }[] for the others, so the primary keeps its shape and no other category changes. The key document-editor.empty-block becomes document-editor.empty-line; document-editor.image is added.

Winter readiness brief

Revised 4 February

Peak demand on the western interconnect is forecast to exceed last winter's record by four percent, and two of the three substations that carried that peak have since been derated. This brief sets out where the exposure sits, what it would cost to close, and which of those costs are already committed.

Where the exposure sits

Substation 14 is the binding constraint. Its transformer bank was derated in September after the oil analysis came back, and the two feeders that would otherwise pick up its load both run through the same corridor, so a fault on either leaves the northern ring supplied from one direction only.

The second concentration is behind the coastal tie. Nothing there has been derated, but the tie has carried an unplanned outage in each of the last three winters and the spares position for its breakers is one deep.

Recommendation

Bring the corridor reconductoring forward by one season and hold the derating until it lands. Everything else in this brief is contingent on that decision.

12 · Collaboration

Comments

About the document, not in it. Create, read, update — through the store.

Threads and comments are rows in commentThreads and comments. The document body is never touched by a comment, and a comment is never lost by an edit: its anchor is { kind: "text", blockId, from: { atom, offset }, to: { atom, offset } }, the same address a mark uses, and it drifts only when its own atom is edited.

The lane

The trailing gutter, outside the paper, reserved: a margin can be set to nothing and text can fill it, where nothing ever runs into the gutter. Icons sit at their anchor's first line, recomputed on relayout; two on one line stack downward.

The tints

A ProseMirror decoration set built from the anchors, so they compose with the selection rather than fighting it.

Writing

Composing on a selection creates the thread and its first comment together, quote frozen from the selected text and within from the anchor. Resolving sets resolution and keeps the row; resolved threads leave the panel and the lane. A thread whose block was deleted shows in the panel as detached, with its quote.
