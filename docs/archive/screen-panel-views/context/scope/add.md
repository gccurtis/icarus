# Add

| View | What it is for | Sections |
| --- | --- | --- |
| Add to this Context | Putting something into either half | By rule · By name |

Two ways to name things: a rule that keeps matching, or a specific thing. The
distinction is the whole model, so it is the panel's structure rather than a
toggle.

Whatever you add lands on the side you are pointing at — Include or Take out.
Both halves accept the same things.

## By rule

Live rules. What they match today is not what they will match tomorrow, and each
row says so.

**Shows**

- *Everything in this project* — Live — includes what is made later
- *Everything of one kind* — All documents, all findings…
- *Another saved Context* — At its current contents

**Needs** — the rule kinds the model supports.

**Open** — "another saved Context, at its current contents" behaves differently
from the other two: it is live in the sense that it re-reads, but the thing it
reads is itself a rule. Nesting depth needs a limit and a cycle check.

## By name

Specific resources, and connectors that stand for many files.

**Shows** — *Q3 Resilience Memo*; *Board Update — October*; *SharePoint — Ops
Reports* — Expands to 312 files

**Needs** — a searchable project resource list, and connector expansion.

**Open** — a named resource that is later deleted needs a resolver contract: fail,
omit, or return an unresolved descriptor. All three are defensible and the model
picks none.
