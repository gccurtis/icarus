# Context types and persistence

## Public type family

The public surface is exported by [`index.ts`](../index.ts).

### `ContextEntry`

`ContextEntry` is defined by [Knowledge](../../../0-platform/knowledge/types.ts) and re-exported by Context to avoid a second reference atom.

```ts
interface ContextEntry {
  id: string;
  kind: string;
}
```

The runtime does not require non-empty strings outside the endpoint parser and does not validate a leaf against the owning resource capability. Set identity is exactly `${kind}:${id}` and is case-sensitive.

### The project entry

```ts
const PROJECT_CONTEXT_KIND = "project";
const PROJECT_CONTEXT_ENTRY = { id: "*", kind: "project" };
const isProjectEntry = (entry: ContextEntry) => entry.kind === "project";
```

One `kind` is not opaque to Context. `project` names the project itself rather than a resource in it, and expands at resolve time to whatever the project currently holds. It is a rule, not a reference — which is the point, because a materialised "everything" is stale the moment anything is added.

The constants live beside the atom in [Knowledge](../../../0-platform/knowledge/types.ts) and are re-exported from `#context`: Context expands the entry, Knowledge recognises it, and neither imports the other.

`isProjectEntry` matches on `kind` alone. A store is built from exactly one `projectId`, so there is no second project an `id` could distinguish, and treating an unusual `id` as an ordinary leaf would silently resolve it to nothing.

### `ContextRecord`

```ts
interface ContextRecord {
  readonly id: string;
  readonly displayName: string;
  readonly description?: string;
  readonly entries: ContextEntry[];
  readonly excludes?: ContextEntry[];
  readonly private: boolean;
  readonly revision: number;
  readonly createdAt: string;
  readonly updatedAt: string;
}
```

| Field | Representation and behavior |
|---|---|
| `id` | Random UUID for declare/composeNamed |
| `displayName` | Caller-provided string; current uniqueness is across the single project table |
| `description` | Optional caller-provided string; nullable SQLite column |
| `entries` | JSON array; declare/update deduplicate by `kind:id` while preserving first occurrence |
| `excludes` | JSON array, absent when empty. Subtracted from the expansion of *this record's* `entries` at resolve time, never at write time. Nested `kind: "context"` excludes expand before subtraction. `update` replaces it only when supplied — omitting it leaves it alone, and `[]` clears it |
| `private` | Set once at declare/composeNamed time from `options.private` (default `false`); `INTEGER 0/1` SQLite column; excluded from `list()` unless `includePrivate` is passed. Immutable after creation — `update` does not change it. |
| `revision` | Starts at 1 and increments on `update`; deletion writes terminal history at current revision +1 |
| timestamps | ISO strings generated by the manager |

### `ContextOperand`

```ts
type ContextOperand = { contextId: string } | { entries: ContextEntry[] };
```

Used only by `composeNamed`. A `contextId` operand is loaded to confirm it exists (throwing `ContextNotFoundError` if it does not) and then stored as a nested `{ id, kind: "context" }` **reference**, not as a copy of its entries — that reference is what keeps the composition live. An `entries` operand is stored verbatim, with no existence check on individual leaves.

### `ProjectMembershipPort`

```ts
interface ProjectMembershipPort {
  listProjectEntries(): Promise<ContextEntry[]>;
}
```

How Context learns what the project currently contains. Registered once during composition via `setProjectMembership`, by `1-init` — the only layer that sees both Context and the resource capabilities. Context itself still knows nothing about what a project holds.

Entries must be spelled the way a caller would spell them, because an exclusion is matched against this expansion.

Until it is registered, and if enumeration throws, a `project` entry expands to **nothing** and the failure is logged. Failing open would silently ground a caller on the whole corpus; an empty result is visible.

### Configuration

[`ContextManagerConfig`](../context.ts) has `maxEntriesPerContext` and `maxResolveDepth`. Current defaults are 100,000 and 10 in [`loadBackendConfig.ts`](../../../0-utils/config/loadBackendConfig.ts).

## Error family

| Error | Payload | Raised by | HTTP mapping |
|---|---|---|---|
| `ContextNotFoundError` | `id` | update, delete, `composeNamed` operand resolution | 404 `not_found` |
| `ContextConflictError` | `displayName` | declare/composeNamed precheck | 409 `conflict` |
| `StaleContextError` | `id`, `current`, `expected` | update's service-level revision check | 409 `stale_revision` |
| `ContextValidationError` | `field`, `reason` | declare/update/composeNamed over `maxEntriesPerContext` on either `entries` or `excludes`, composeNamed's empty `displayName` | 400 `context_invalid` |
| ordinary `Error` | message only | SQLite failures, other unclassified inputs | 400 `bad_request` |

`options?: ContextWriteOptions` on `declare`/`composeNamed` is `{ description?: string; private?: boolean; excludes?: ContextEntry[] }` — an options object, not further positional parameters. `update` takes a fourth parameter `{ excludes?: ContextEntry[] }` for the same reason.

There are no implemented cycle/depth error classes. Resolution silently omits cycles, missing contexts, and over-depth branches on the **include** side.

On the **exclude** side it does not: a cycle or depth cut while expanding an exclusion list resolves that record to nothing and logs at error. An omission on the include side gives you less than you asked for, which is harmless; the same rule on the exclude side would hand back exactly the resources someone said to withhold.

## Runtime and store interfaces

[`ContextManager`](../context.ts) is asynchronous at its boundary even though the current store is synchronous. Its full methods are documented in [Runtime](runtime.md).

[`ContextStore`](../store.ts) exposes:

```ts
interface ContextStore {
  get(id: string): ContextRecord | undefined;
  getByName(displayName: string): ContextRecord | undefined;
  list(includePrivate: boolean): ContextRecord[];
  insert(record: ContextRecord): void;
  update(record: ContextRecord, expectedRevision: number): boolean;
  delete(id: string, recordedAt: string): number | undefined;
  purge(id: string): "purged" | "current" | "missing";
  history(id: string): ResourceHistoryRecord<ContextRecord>[];
  pruneHistory(cutoff: string): number;
  purgeExpired(cutoff: string): number;
}
```

The update return value is the SQLite compare-and-swap result. Delete returns
the terminal revision when a current row existed. The port has no `close`
method.

## SQLite representation

[`SQLiteContextStore`](../sqlite-store.ts) opens `./data/contexts.db` in WAL mode. It derives one trusted 16-hex prefix:

- `ctx_${sha256(projectId).slice(0,16)}_contexts` — current records only
- `ctx_${sha256(projectId).slice(0,16)}_history` — superseded snapshots and terminal deletion records

The current table stores `entries_json`, `excludes_json`, a nullable
`description`, plus record metadata. A unique index enforces exact,
case-sensitive `display_name` uniqueness among current rows.

`excludes_json` is `NOT NULL DEFAULT '[]'` and is added with `ALTER TABLE` when
absent, because `CREATE TABLE IF NOT EXISTS` never revisits an existing table —
a database created before the column shipped would otherwise read it back as
`undefined`. `rowToRecord` also tolerates the column being missing entirely, so
history snapshots archived before the change still decode.

| Store method | SQL visibility |
|---|---|
| `get` | Selects a current row by ID |
| `getByName` | Selects an exact current display name |
| `list` | Current rows only; optionally applies `private = 0` |
| `insert` | One `INSERT`; SQL primary key and current-name index apply |
| `update` | In one transaction, archives expected revision then replaces current by `id + revision` CAS |
| `delete` | Archives current, appends terminal revision, and removes current in one transaction |
| `purge` | Rejects current rows; removes history only when its latest record is terminal deletion |
| retention | Prunes old current-resource snapshots and purges terminally deleted resources after cutoff |

No wire-specific type exists: endpoint responses serialize `ContextRecord` directly, and request parsing builds simple `{id, kind}` objects.
